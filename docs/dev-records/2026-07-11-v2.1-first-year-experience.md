## 目标与边界

V2.1 解决首局目标不清、行动入口密集和第一年缺少阶段反馈的问题，不扩行动、事件、职业、结局、后端、账号、排行榜或付费，也不修改工资、Offer 概率、随机数、危机和核心成长公式。

第一年体验只对新建普通局启用。旧存档和每日挑战保持原行为，建议只提供可解释提示，不自动执行行动。

## 主要改动

1. **新局主命令**：启动页显示职业、城市和价值观摘要；普通新局是主命令，每日挑战降为次命令。
2. **第一年目标带**：从真实 `GameState` 派生“建立入场券、进入机会链、站稳第一份工作”三个阶段，最多显示三个节点和一个可执行建议。
3. **行动建议**：复用 `chooseActionForStrategy(state, 'stable_cashflow')` 的危机与机会顺序；玩家手动切换分类后当月保持选择，跨月再按状态更新。
4. **第一年度复盘**：第 12 月以后在无事件、无结局时自动出现一次，展示指标、关键选择、优势、风险和下一步；确认后可从时间轴回看。
5. **弹窗优先级**：待处理事件 > 人生结局 > 玩家主动工具 > 第一年度复盘。
6. **工具降噪**：成就、商店、脚本、收藏、保存和换角色进入一个键盘可用菜单；撤销继续直接可见。
7. **兼容性**：旧存档与每日挑战不写第一年资格；人生脚本同时支持“接受当前 Offer”和旧名称“在职跳槽”。
8. **浏览器修正**：站点使用打包 favicon，控制台不再产生 `/favicon.ico` 404；1200px 以下将反馈和命令入口停靠到正常文档流，避免覆盖内容。
9. **合入前审查修正**：年度建议消费最高风险；当前 Offer 使用统一到期判定；跨月搜索不再隐藏新建议；结局后不再显示失效引导。

## 残余风险

- 推荐质量仍依赖现有 `stable_cashflow` 策略和行动数据；本版本没有改变数值平衡。
- 固定单局仍可能在第 12 月进入现金流陷阱；72 场景总体门槛通过，不能解读为每局都应成功。
- 第一年度资格使用 `flags`，未来新模式创建状态时必须明确是否启用，不能默认复制普通新局逻辑。
- 行动显示名仍是人生脚本 DSL 的用户接口；再次改名时必须更新预设、原始 CSV、运行时 JSON 和兼容别名。
- 部分 jsdom 懒加载 UI 测试仍有 React `act()` 时序警告；真实浏览器控制台为 0 error / 0 warning，后续测试基建批次应统一收敛异步渲染辅助函数。
