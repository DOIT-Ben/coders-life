# 前端演进规划报告（Roadmap）

- 日期：2026-07-04
- 范围：程序员人生模拟器 V6 前端与体验层的下一阶段演进
- 性质：规划报告（未开工；每个批次开工前按项目规则出各自的实施细案）
- 基线：终端化重设计已完成（主题/commit log/命令面板/P0 告警/对比度守卫/响应式打磨），182 测试全绿，CI 绿，master 已推送

## 一、第一性原理：下一阶段的核心命题

外壳已经完成"说程序员母语"的改造，用户第一眼的身份识别问题解决了。下一阶段的核心命题变为两个：

1. **留存**：第一眼被吸引之后，玩家为什么第二天还来？现状短板：结局表达单薄（一条日志+弹窗）、多周目缺少变化动力、单局数值偏难（同 seed 基线 12 个月触发现金流陷阱）。
2. **传播**：程序员群体的传播靠"晒"。现状没有任何可分享物——没有战报卡片、没有可比较的挑战、没有"我的人生 diff"。

工程侧的对应命题：把本轮欠下的结构债（超限文件、lint 警告、死代码）在功能加码前清掉，避免债滚债。

## 三、复用 / 适配 / 自研判断

| 事项 | 结论 |
|---|---|
| 结局 Postmortem | **复用**现有 turningPoints/decisionLog/endings 数据，自研展示层（纯前端，无新依赖） |
| 分享卡片 | **适配** Canvas 绘制离线生成 PNG（零依赖），文案复用 Postmortem 数据；不引入 html2canvas 类库（体积与字体兼容成本） |
| 每日挑战 | **复用**确定性种子引擎 + 回放哈希；纯本地版零后端即可上线（日期→seed），排行榜属后端范围单独评估 |
| 人生脚本 | **自研**受限 DSL（白名单条件/动作），**明确不做** JS eval 沙箱（安全边界大，收益不成比例）；执行器复用 autoChoiceSystem 模式 |
| 工程清债 | 全部复用既有模式（组件拆分沿用 panels.tsx 先例，契约测试迁移沿用本轮流程） |

## 四、分批次落地方案

### 批次 1：工程清债（先清债后加码，约 1 个工作日）

1. **GameDialogs 拆分**（589 行超限）：按对话框拆为 dialogs/ 目录多文件；契约测试断言同步迁移。
2. **消除 4 个 lint 警告**：两处 set-state-in-effect 改为事件处理器内派生/受控 key 重置；两处 useMemo 依赖显式化。完成后把 `react-hooks/set-state-in-effect` 从 warn 升回 error，护栏收紧。
3. **死代码清理**：删除 6 个未引用组件（WorldStatusBar/DebugPanel/StatPanel/ActionPanel/ShopModal/AchievementModal）及对应契约断言；同时清理 app.css 中失效的 .log-bubble 旧样式。
4. 验收：测试全绿、lint 0 error 0 warning、build 通过、契约测试仍覆盖等价保证。

### 批次 2：结局 Postmortem + 分享卡片（留存+传播，约 2-3 个工作日）

1. 结局弹窗重构为**人生复盘报告**：故障时间线（关键转折点）、根因分析（结局触发条件的人话解释）、影响面（终局数值对比开局）、改进项（下一局建议）——全部来自现有数据，零引擎改动。
2. **战报卡片**：Canvas 生成可保存 PNG（终端风格：结局名+关键数值 diff+短哈希+天数），一键复制/下载。
3. 验收：三类结局（失败/平衡/成功）各自渲染正确；卡片在微信/推特常见比例下清晰；移动端可长按保存。

### 批次 3：每日挑战（回访钩子，约 2 个工作日，纯本地版）

1. 日期派生 seed（如 `YYYYMMDD` 哈希），全球玩家同一开局；标题页入口「今日人生」。
2. 结算接批次 2 的战报卡片（带日期戳），天然形成"晒今日结局"传播循环。
3. 本地历史记录（近 30 天成绩曲线）。排行榜需后端，此批次不做，留接口。
4. 验收：同日同选择结局一致（确定性）；跨日切换正确；历史记录迁移安全。

### 批次 4：人生脚本（差异化杀手锏，约 1 周，需单独实施细案）

1. 受限 DSL：`当 精神<40 则 睡眠修复` 式白名单规则，UI 表单+文本双编辑；引擎侧复用 autoChoiceSystem 执行。
2. 挂机跑局 + 加速回放；脚本与 seed 一起构成可分享的"策略"。
3. 风险最高的一档：规则表达力、平衡性（自动化最优解会暴露数值漏洞，正好反哺调参）、循环保护。开工前单独出设计文档。

### 持续项（不占批次）

- **数值平衡观察**：`stable_cashflow` 同 seed 12 个月现金流陷阱偏难的问题，建议先收集真实玩家结局分布（反馈入口已有），再决定调参幅度——数据先于手感。
- **性能**：批量模拟的 structuredClone 热点，等调参频率上来再优化，不预支。
- **可访问性**：命令面板焦点圈闭、j/k 列表键航，随批次 1 顺手做。

## 五、风险与验证标准

| 风险 | 等级 | 缓解 |
|---|---|---|
| GameDialogs 拆分回归 | 中 | 契约测试逐条迁移 + 全量 UI 测试 + 手工过一遍所有弹窗 |
| set-state-in-effect 重构改变渲染时序 | 中 | 逐处小步改，每处跑 monthlyPlanUi/undoPill 相关测试 |
| Canvas 卡片中文字体跨端渲染差异 | 低 | 用系统字体栈 + 实机截图验收 |
| 每日挑战被改本地时间作弊 | 低 | 纯本地版不设防（无排行榜即无收益），后端版再校验 |
| 人生脚本平衡性冲击 | 高 | 单独立项 + 批量模拟先跑脚本策略全矩阵，releaseGate 扩展脚本场景 |

**统一验收线**（每批次）：`npm run lint` 0 error、全量测试绿、`npm run build` 通过、同 seed simulate 与基线一致（引擎无关批次）、批量模拟 releaseGate 通过（引擎相关批次）、三档视口手工过、用户可见层审计、CI 绿后推送。
