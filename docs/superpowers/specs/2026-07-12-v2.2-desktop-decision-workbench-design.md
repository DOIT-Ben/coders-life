# V2.2「桌面决策工作台」布局设计

- 状态：已批准方向，待书面规格复核
- 日期：2026-07-12
- 基线：`v2.1` / `bc7a26581339e6dc8641b523e7b01b3edbd66c7c`
- 目标视口：桌面 1920×1080、浏览器 100% 缩放
- 目标用户：中国程序员与技术从业者
- 范围：主游戏页信息架构、桌面密度、滚动边界与响应式布局

## 1. 第一性原理

玩家进入主游戏页时，最重要的任务不是浏览所有历史，而是完成当月决策。因此首屏必须按以下顺序回答：

1. 当前处于什么阶段，本月主要目标是什么；
2. 哪些核心状态会影响本次决策；
3. 现在能执行哪些行动，各自收益、成本与风险是什么；
4. 需要追溯时，去哪里查看时间轴、日志和项目历史。

当前页面把第一年进度、四张核心指标卡、五项现实压力、危机提示、时间轴、日志和行动列表全部作为一级内容纵向排列。与此同时，左右主列固定为 `min(72dvh, 680px)`，没有扣除上方内容高度；行动栏固定为 320px，分类与搜索又占据多行。这导致桌面首屏出现页面滚动和面板内部滚动叠加，行动列表成为最窄、最晚出现的核心区域。

V2.2 的目标是把主游戏页从“状态卡片陈列页”调整为“当月决策工作台”。不减少数据，不改变规则，只改变信息优先级与展示密度。

## 2. 成熟方案与复用判断

### 2.1 复用的浏览器能力

- CSS Grid：用于构建明确的任务条、状态带和行动工作区，不引入新的布局库。
- 动态视口单位 `dvh`：用于计算工作区可用高度，避免移动浏览器工具栏和固定 `vh` 带来的误差。
- 容器查询：组件根据自身可用宽度切换密度，而不是只根据整个窗口宽度猜测。
- `minmax(0, 1fr)`、`min-height: 0` 和单一内部滚动容器：避免 Grid/Flex 子项撑破视口。
- WCAG 2.2 Target Size Minimum：桌面高密度模式仍保留至少 24×24 CSS px 的可操作目标；移动端沿用项目现有 44px 触控目标。

一手资料：

- MDN CSS Grid：https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Grid_layout
- MDN 动态视口单位：https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/length
- MDN 容器查询：https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Containment/Container_queries
- W3C WCAG 2.2 Target Size：https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html

### 2.2 复用 / 适配 / 自研

- 复用：现有 `FirstYearProgressBand`、`StatCard`、`PressureSummary`、行动筛选和行动详情逻辑。
- 适配：把阶段目标、核心状态和现实压力改成紧凑展示变体；把行动分类、搜索与管理入口收敛到单行工具栏。
- 必要自研：新增纯展示层的工作台编排组件或语义容器，负责桌面信息顺序和折叠边界。
- 不引入：UI 框架、拖拽布局、用户自定义仪表盘、后端配置、额外持久化状态。

## 3. 方案比较

### 方案 A：只压缩现有 CSS

缩小 padding、字号和卡片高度，保持当前 DOM 顺序。

- 优点：改动最小。
- 缺点：信息层级不变，仍存在双重滚动；稍小视口会再次失效。
- 结论：不采用。

### 方案 B：桌面决策工作台

将阶段与状态压缩为顶部控制带，行动选择成为主工作区，日志和项目历史降为次级区域。

- 优点：与玩家当月决策任务一致；能显著扩大行动区；不改变游戏逻辑。
- 缺点：需要调整 `GameScreen` 组件编排和若干契约测试。
- 结论：采用。

### 方案 C：行动 / 状态 / 日志分页

主游戏页只显示一个页签内容。

- 优点：单页最清晰。
- 缺点：比较状态与行动时需要反复切换，增加操作成本。
- 结论：不采用。

## 4. 信息架构

桌面主游戏页按四层组织：

1. **游戏工具栏**：角色、天数、年龄、撤销和工具菜单。
2. **决策上下文**：第一年阶段、主目标、三个进度节点、本月建议。
3. **核心状态带**：四项核心能力和五项现实压力；异常状态优先高亮。
4. **行动工作区**：行动分类、搜索、管理和行动列表，成为首屏主体。

次级内容移动到行动工作区之后：

- 生存时间轴；
- 人生日志；
- 项目进度。

次级内容默认以“履历与日志”区块呈现，不参与首屏高度预算。它可以保留现有滚动日志，但页面首屏不能依赖用户先穿过日志才能操作行动。

危机信息不并入普通状态卡。存在 P0 危机或精神危急时，在状态带与行动区之间显示单行警报；无危机时不保留占位高度。

## 5. 桌面布局

### 5.1 高度预算

以 1080px 高视口为基准：

| 区域 | 目标高度 |
|---|---:|
| 页面外边距与紧凑标题 | 56–72px |
| 游戏工具栏 | 40–48px |
| 第一年度任务条 | 56–64px |
| 核心状态带 | 72–80px |
| 区域间距与可选警报 | 24–52px |
| 行动工作区 | 剩余空间，最低 560px |

行动工作区采用基于实际剩余空间的布局，不继续使用孤立的 `72dvh`。页面在 1920×1080 下不应为了进入行动区而滚动。

### 5.2 宽度与密度

- 主容器桌面最大宽度从当前 1040px 调整为约 1360–1440px，并保留响应式左右边距。
- 行动列表在宽容器中采用两列；单卡最小宽度约 360px。
- 低于双列可读宽度时自动退回单列，不强行缩字。
- 行动卡默认只展示名称、最多三项效果、时间/精力成本和一条风险或收益摘要。
- 完整描述、证据文本和额外状态保留在“详情”中。

### 5.3 行动工具栏

- 分类使用一行分段控件，可横向滚动但不换成两到三行。
- 搜索框与“管理”位于同一行右侧。
- 当前分类始终可辨识，键盘焦点样式保留。
- 工具栏固定在行动工作区顶部；只有行动列表内部滚动。

## 6. 组件调整

### `GameScreen`

- 只负责工作台区域编排和状态传递。
- 将履历类内容放到行动工作区之后。
- 不引入新的游戏状态或存档字段。

### `FirstYearProgressBand`

- 增加桌面紧凑布局：阶段与主目标左对齐，三个节点居中，本月建议右对齐。
- 任务条最多两行；长文案截断或自然换行时不能推高到第三层卡片高度。

### `StatCard` 与 `PressureSummary`

- 提供紧凑状态单元，不再呈现九个独立大卡片。
- 核心能力保留数值和短进度条。
- 现实压力使用名称、数值和语义色标识；正常状态降低视觉权重，危险状态提高权重。
- 颜色不是唯一提示，仍保留标签和数值。

### 行动区

- 现有筛选、推荐、收藏、详情与执行逻辑保持不变。
- 行动卡展示密度改变，但按钮语义和键盘可访问性保持不变。
- 桌面操作目标不小于 24×24px；移动端继续不小于 44px。

### 履历与日志

- 时间轴、日志和项目进度形成一个独立次级区域。
- 日志仍可内部滚动，但不与行动列表在同一首屏内争夺高度。
- 不删除任何历史数据和现有入口。

## 7. 响应式策略

- **≥1280px**：完整决策工作台；状态带单行；行动双列。
- **900–1279px**：任务条允许两行；状态带可分为两行；行动单列或双列由容器宽度决定。
- **661–899px**：行动仍优先于日志；分类横向滚动；状态单元缩为两至三列。
- **≤660px**：保持移动端单列和 44px 触控目标；任务、状态、行动、履历按顺序排列，不套用桌面固定高度。
- **低高度桌面（≤800px 高）**：隐藏非必要辅助文案，进一步压缩标题与状态带，但不缩小正文到不可读尺寸。

## 8. 明确不做

- 不修改行动、事件、概率、数值结算或第一年引导逻辑。
- 不删除核心指标、现实压力、日志、时间轴或项目数据。
- 不增加可拖拽、自定义排序或保存布局偏好。
- 不重做主题系统和职业选择页。
- 不在本次处理 `favicon.ico` 等无关问题。

## 9. 验收标准

### 9.1 1920×1080 首屏

- 浏览器 100% 缩放时，无需页面滚动即可看到当前阶段、核心状态、全部行动分类和至少 4 张完整行动卡。
- 行动工作区是首屏面积最大的区域。
- 页面不出现页面滚动与行动列表滚动同时争夺同一方向手势的情况。
- 不出现文本遮挡、卡片裁切、按钮重叠或横向溢出。

### 9.2 功能与可访问性

- 行动分类、搜索、推荐、执行、收藏、详情和管理入口行为不变。
- 危机警报、第一年复盘入口和状态语义不丢失。
- 键盘可以访问所有交互元素，焦点可见。
- 颜色之外仍有文字或数值表达状态。

### 9.3 验证矩阵

- Playwright：1920×1080、1440×900、1280×720、768×1024、390×844。
- 三套主题：终端黑、极简白、纯黑。
- 浏览器控制台和网络错误为 0。
- 对桌面截图执行可见区域检查，确认至少四张完整行动卡。
- Vitest、TypeScript、ESLint、生产构建和既有模拟门槛保持通过。

## 10. 风险与回退

| 风险 | 等级 | 控制方式 |
|---|---|---|
| 紧凑化导致文字难读 | 高 | 不按视口缩放字体；限定最小字号和卡片宽度 |
| 行动卡精简后信息不足 | 中 | 核心收益、成本、风险保留；完整内容进入详情 |
| 日志下移后难以发现 | 中 | 保留明确的“履历与日志”标题及工具菜单入口 |
| 固定工作区在低高度屏失效 | 高 | 使用动态剩余高度和低高度媒体查询，不写死单一高度 |
| 契约测试依赖源码结构 | 中 | 逐项迁移现有源码断言，不删除等价护栏 |

本次只调整展示层，可通过回退布局提交恢复 `v2.1` 页面；游戏状态、存档和规则无需迁移或回滚。
