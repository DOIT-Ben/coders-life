# 前端润色与主题系统设计

- 日期：2026-07-06
- 分支：`feat/v6-frontend-polish-themes`
- 范围：程序员人生模拟器 V6 前端表现层、主题系统、弹窗/行动区滚动、前端接线测试
- 不在范围：核心数值公式重写、结局规则重写、引擎架构重构、后端服务

## 1. 第一性原理

本轮目标不是把界面换一层皮，而是补齐三个真实体验缺口：

1. 玩家需要明确可选的纯白和纯黑界面，且切换后所有游戏功能仍保持可读、可点、可滚动。
2. 弹窗和右侧行动区必须在真实窗口尺寸内可用，不能出现关闭按钮被挤出视口、行动列表显示不全却没有稳定滚动边界的问题。
3. “逻辑感觉错误”需要转成可复现的前端链路问题，先用接线测试证明问题存在或闭环，再修前端接线、提示、反馈和状态展示；没有证据时不改核心公式。

成功标准是：玩家能在游戏内切换 `终端黑 / 极简白 / 纯黑`；商店、反馈、脚本、结局、行动详情等弹窗的头部和操作区稳定，内容区内部滚动；右侧行动列表在行动较多时持续可滚动；前端提示与真实代码效果一致；测试和构建通过。

## 2. 现状证据

已审查当前代码与测试：

- 当前只有单套深色终端 token，未发现 `data-theme`、主题切换控件、主题持久化或系统色偏好处理。
- `src/styles/app.css` 使用了 `var(--accent-soft)`，但 token 区未定义该变量，成功类徽章背景会失效。
- 商店、反馈、脚本、结局弹窗各自写 `max-height`，滚动策略分散；`ModalShell` 有基础弹窗壳，但没有统一的“头部固定、内容滚动、底部固定”契约。
- 右侧行动区已有 `overflow-y: auto`，但分类区、搜索区、辅助区会挤压主列表，窗口高度较小时体验不稳定。
- `v1FrontendContract.test.ts` 有源码级滚动契约，但缺少主题持久化、缺失 token、弹窗固定头部、行动区滚动边界的更直接测试。
- 当前基线 `npm test` 通过 226 个测试，`npm run build` 通过。

## 3. 可复用方法

采用项目已有方法，不引入运行时依赖：

- 主题复用 CSS Custom Properties 和项目 `:root` 语义 token 体系。换肤只覆盖 token 值，不重写组件结构。
- 主题状态用 React 本地状态 + `document.documentElement.dataset.theme` + `localStorage` 持久化。
- 弹窗复用 `ModalShell`，在壳层统一布局契约，不让每个对话框各自解决关闭按钮和滚动。
- 前端逻辑审查复用项目 `frontend-review` 的三问：能否到达、不可用时是否知道原因、成功后是否有反馈。
- 验证复用现有 Vitest、契约测试、对比度测试、构建和模拟门禁；真实浏览器视口验证作为实现阶段验收项。

## 4. 推荐方案

采用方案 A：保留当前程序员终端风格，新增 `终端黑 / 极简白 / 纯黑` 三套主题。

### 4.1 主题系统

新增主题类型：

- `terminal`：现有终端黑，作为默认主题。
- `paper`：极简白，强调白底、浅灰边界、克制蓝/绿/红语义色。
- `blackout`：纯黑，强调 `#000` 页面底、深灰面板和高对比文本。

实现方式：

- 在 `src/App.tsx` 或独立轻量模块中维护主题状态。
- 首屏只引入轻量主题逻辑，不静态引入 `saveManager` 或 `config/events`。
- `document.documentElement.dataset.theme = theme`。
- `localStorage` key 使用独立名称，例如 `coderslife_theme`。
- `index.html` 的 `theme-color` 可由运行时代码同步，避免移动浏览器地址栏颜色与主题冲突。
- 主题切换入口放在标题卡或全局工具区，不放进游戏行动按钮。

样式约束：

- 所有新增颜色进入 token，不在组件内新增裸 hex。
- 修复缺失的 `--accent-soft`。
- 将常用透明阴影和 overlay 收敛成 token，例如 `--overlay`、`--focus-ring`、`--shadow`。
- 保留现有语义：正向绿色、风险红色、警示琥珀、信息蓝。

### 4.2 弹窗滚动

统一 `ModalShell` 的结构契约：

- `.modal` 是视口内 flex column，`max-height: calc(100dvh - safe padding)`。
- `.modal-head` 固定在顶部，不参与内容滚动。
- `.modal-scroll` 是唯一主滚动区，`flex: 1 1 auto; min-height: 0; overflow-y: auto`。
- `.modal-actions` 固定在底部，不参与内容滚动。
- 移动端弹窗接近全屏但保留安全边距，关闭按钮始终不被内容推走。

各弹窗只保留内容密度差异，不再各自用互相冲突的高度规则控制整体可用性。

### 4.3 右侧行动区

行动区保持“固定边界 + 主列表滚动”：

- `.right-col` 和 `.action-card` 明确视口内高度上限。
- `.action-hdr`、`.action-tabs`、搜索框固定在列表上方。
- `.action-list` 是主要滚动区，任何分类行动过多时只滚动列表。
- `.action-support-scroll` 保留为辅助信息区，但设置稳定最大高度，不能吞掉行动列表。
- 移动端保持单列，行动区高度不超过视口主要区域，列表内部滚动。

### 4.4 前端逻辑审查

本轮不泛改核心公式。只处理可证据化的前端链路问题：

| 问题类型 | 证据来源 | 修复原则 |
|---|---|---|
| 主题切换不存在 | 源码无 `data-theme`/主题控件/持久化 | 新增真实入口、持久化、测试 |
| 缺失 CSS token | `var(--accent-soft)` 未定义 | 补 token 并加测试防回归 |
| 弹窗关闭不易点 | 弹窗高度规则分散，用户已反馈商店太长 | 壳层统一固定头部和内容滚动 |
| 行动列表显示不全 | 右侧区域被分类/辅助区挤压 | 主列表固定为核心滚动区 |
| 不可用操作像假功能 | disabled 有原因但部分入口反馈弱 | 增加接线测试，确保原因可见或点击有中文反馈 |
| 成功反馈不明显 | 商店购买、撤销、保存等链路分散 | 保持日志/toast/状态反馈一致 |

## 5. 测试方案

新增或更新测试：

1. 主题测试
   - 扫描 `app.css` 中所有 `var(--*)`，断言每个变量在默认 token 或主题 token 中有定义。
   - 校验 `terminal / paper / blackout` 三套主题关键文本对比度。
   - UI 测试验证主题按钮可切换、刷新后从 `localStorage` 恢复。

2. 弹窗测试
   - 契约测试断言 `ModalShell` 具备固定头部、滚动内容和固定操作区结构。
   - 商店弹窗、反馈弹窗、脚本弹窗打开后都使用统一滚动容器。

3. 行动区测试
   - 契约测试断言右侧行动列表是主滚动区，辅助区有高度约束。
   - UI 测试覆盖行动分类切换后仍能看到列表和管理入口。

4. 前端接线测试
   - 商店购买后按钮状态和拥有状态可见。
   - 不可执行行动展示中文原因。
   - 反馈入口仍独立于游戏行动按钮。

5. 回归门禁
   - `npm test`
   - `npm run build`
   - `npm run simulate`
   - `npm run simulate:batch`
   - `git diff --check`

真实浏览器验收：

- 390px、768px、1280px 三档视口检查无横向溢出。
- 在 390px 视口打开商店、反馈、脚本、结局弹窗，关闭按钮可见且可点。
- 在行动较多分类中确认右侧列表可滚动。
- 三套主题分别检查首屏、游戏页、弹窗、行动卡、终端面板。

## 6. 风险与缓解

| 风险 | 等级 | 缓解 |
|---|---|---|
| 契约测试依赖源码字符串，样式调整易误伤 | 高 | 只改相关断言，不删除等价护栏 |
| 白色主题对比度不足 | 中 | 扩展 `themeContrast.test.ts` 覆盖三主题关键 token |
| 主题逻辑污染首屏 chunk | 中 | 主题模块保持轻量，禁止静态引入存档和事件数据 |
| 弹窗统一布局影响某些对话框 | 中 | 逐个对话框补接线测试，先壳层后局部样式 |
| 真实浏览器不可用导致视口验证不足 | 中 | 自动测试先守结构；部署前必须手动或补可用浏览器验证 |

## 7. 实施顺序

1. 增加主题类型、主题状态、主题切换入口和持久化。
2. 扩展 CSS token，补 `terminal / paper / blackout` 三套主题值，修复 `--accent-soft`。
3. 统一 `ModalShell` 布局和弹窗滚动规则。
4. 调整右侧行动区主滚动和辅助区高度。
5. 增加主题、缺失 token、弹窗滚动、行动区滚动、前端接线测试。
6. 运行完整验证并记录结果。

## 8. 不做项

- 不重写游戏核心公式。
- 不新增运行时依赖。
- 不把反馈按钮放回游戏行动功能区。
- 不移除当前 V1 风格和移动端布局，只在其上增强主题与滚动稳定性。
- 不用 `{}` 或文案掩盖真实逻辑问题；逻辑疑点必须先有可复现证据。

## 9. 自审结论

- 无未决项。
- 范围聚焦在前端主题、滚动和接线反馈，不触碰无关模块。
- 主题、弹窗、行动区、测试、验证均有明确验收证据。
- “逻辑感觉错误”已限定为前端链路审查，不以主观感觉直接改引擎。
